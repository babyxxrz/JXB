# 协作规范(JXB 项目组规)

目标:四人按模块分工写代码、最后整合而不混乱。本规范为组内共同约定,冲突时以本文档和《技术设计文档》第 7 章接口契约为准。

## 一、仓库与分支

- `main` 分支只放联调通过的代码;任何人**不直接向 main 提交**。
- 每人一个常驻分支(严晨越 = `ycy`,其他人按姓名拼音类推),功能改动只进自己的分支,合入 main 走 PR。
- 目录按模块划分,**只写自己的目录,不改别人的**:

```
JXB/
├── docs/      # 公共文档(接口样例消息、协作规范、演示流程)
├── web/       # Web 看板前端(严晨越)
├── server/    # 记录服务后端(严晨越)
├── vision/    # 数据采集标注、模型训练与端侧部署(杨泽 / 张鹏源)
└── control/   # 标定与机械臂控制(朱玉贺)
```

- 提交信息带模块前缀:`feat(web): …`、`fix(control): …`、`docs: …`。
- 拉取代码前先 `git pull`;提交前先 `git status` 自查,不提交临时文件(`~$*.docx`、`__pycache__/` 等,仓库已用 .gitignore 排除)。

## 二、接口契约是唯一真理

1. 字段名、类型、单位、枚举值**照抄**《技术设计文档》第 7 章,不许改名、换单位。
2. 每个接口先写**样例消息(JSON)**放进 `docs/接口样例.md`,联调双方对着同一份样例验证。
3. 空值约定:未知坐标用 `null` 不用 `0`;无目标返回空数组;时间戳统一 Unix 毫秒(int64)。
4. 错误码只允许文档中的四个起步:LOW_CONFIDENCE / OUT_OF_WORKSPACE / CONTROL_TIMEOUT / STOP_REQUESTED;新增错误码先改文档再写代码。
5. 幂等必须落地:相同 event_id 不重复入库、相同 task_id 不重复执行。
6. 接口不一致时:以文档为准改代码,不许"顺手改接口"。

## 三、模块自带 mock,不依赖别人也能跑

- 交付时,自己的模块**没有队友也能独立演示**:无机械臂就发模拟事件,无模型就放固定检测结果。
- 一切模拟数据必须明确标记"模拟",不得冒充实机验收结果。
- 联调先 mock 对 mock,再逐步替换真实实现。严晨越的 `/api/events` 入库接口与 mock 引擎是 task_event 的标准参照,朱玉贺的控制模块照此对接。

## 四、联调节奏(按倒排计划执行)

- T−4 周:接口 mock 联调,四人按样例消息互发,通了才算模块完成。
- T−2 周:真实分拣闭环跑通一次。
- 联调发现对方问题:发消息或提 issue,**不直接改对方代码**。

## 五、验收数字挂嘴上

| 成员 | 对应验收 |
|---|---|
| 杨泽 / 张鹏源 | F1:积木 mAP@0.5 ≥ 0.75;端侧单帧推理 P95 ≤ 150ms;平面定位误差 ≤ 10mm |
| 朱玉贺 | F2:工作区 ≥ 120×120mm;连续 10 次成功 ≥ 8 次;单次 ≤ 20s 完成或报告失败 |
| 严晨越 | F3:4 个页面;事件写入至展示 ≤ 1s;20 条记录完整率 100% |

提交前自测自己对应的数字,不把未测代码交给别人联调。

## 六、交付即"能跑"

- 依赖写进 requirements.txt;启动方式写进 README,**三步:装依赖 → 启动 → 访问地址**,队友 5 分钟跑不起来 = 未交付。
- 待定项(技术设计第 11 章 T1–T14)确认后先回填文档再动代码。
