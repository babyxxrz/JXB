# Web 看板演示流程(严晨越)

答辩/验收演示脚本,含模拟演示与真实联调两条路径。所有模拟数据页面均明确标注,不冒充实机验收。

## 准备

1. 克隆仓库,切到 `ycy` 分支(或含看板代码的合并分支)。
2. 启动记录服务(托管前端 + API):

```bash
cd server
pip install -r requirements.txt
python -m uvicorn app.main:app --port 8000
```

3. 浏览器打开 http://127.0.0.1:8000 。

## 路径 A:纯模拟演示(无硬件,默认)

1. **运行监控**:点「启动任务」→ 观察开机自检三项依次通过(舵机位置/RGB 灯/蜂鸣器)→ 状态变为「运行中」→ 实时事件流开始滚动(排队→执行→成功/失败/跳过,含 HSV 兜底与错误码)。
2. **任务记录**:展示按颜色/状态筛选与分页,指出「事件写入至展示 ≤1s、20 条完整率 100%」对应验收 F3。
3. **分类统计**:切换时间范围,展示 KPI(成功率对照 80% 验收线、平均耗时对照 20s 上限)、各颜色分拣结果、状态分布、最近任务耗时(20s 上限参考线)。
4. **参数配置**:修改置信度阈值/RGB 模式/蜂鸣器并保存;任务运行中再打开页面,展示运动参数被锁定(契约:运动中禁止修改)。
5. **停止任务**:点「停止」,≤1s 内状态回「待机」,在途任务记为「已停止 / 收到停止请求」。
6. 演示动作:待机时选择「挥手/舞蹈」点执行,展示联调演示能力。
7. 说明:页面顶部「演示模式 · 模拟数据」徽章即模拟标记;真实模式该徽章会移除(见下)。

## 路径 B:真实联调(朱玉贺控制模块就绪后)

1. 后端以 `JXB_CONTROL=real` 启动(待定项 T1/T7 确认后实现桥接)。
2. 前端切换真实数据源:`web/assets/js/core/config.js` 中 `api.mode = 'real'`。
3. 朱玉贺侧按 `docs/接口样例.md` 的 task_event 样例 POST 到 `/api/events`,看板 1s 轮询内呈现。
4. 启动/停止经由 `/api/command` 下发,返回 accepted 即受理。
5. 演示前跑一遍 `python tests/latency_report.py`,携带最新《数据延迟测试记录》作点验材料。

## 故障注入演示(对应验收 F4)

在模拟路径下:跳过事件 = LOW_CONFIDENCE→HSV 兜底失败;失败事件含三种错误码;停止请求 = STOP_REQUESTED。三类异常各注入 3 次即可现场演示异常处理路径。
