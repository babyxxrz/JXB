# 控制模块接口与联调说明（朱玉贺 → 张鹏源 / 严晨越）

对应《技术设计文档》第 5、7 章。所有接口定义在 `dofbot_info` 功能包，
单一事实来源，本组统一使用。

## 1. 话题与服务总览

| 名称 | 类型 | 方向 | 说明 |
|---|---|---|---|
| `/task_event` | `dofbot_info/msg/TaskEvent` | 朱玉贺 → 严晨越 | 任务事件流（7.4），看板订阅入库 |
| `/control_status` | `dofbot_info/msg/ControlStatus` | 朱玉贺 → 全体 | 控制状态广播（state/busy/mode），看板与闭环使用 |
| `/detect_result` | `dofbot_info/msg/DetectResult` | 张鹏源 → 朱玉贺 | 一帧检测结果（7.2），分拣闭环订阅 |
| `/pick_place` | `dofbot_info/srv/PickPlace` | 张鹏源触发 / 朱玉贺执行 | 抓取-搬运-释放动作（7.3） |
| `/task_command` | `dofbot_info/srv/TaskCommand` | 严晨越 → 朱玉贺 | start/stop 启停（7.5） |
| `/play_action_group` | `dofbot_info/srv/PlayActionGroup` | 看板 → 朱玉贺 | 演示动作组（5.4） |
| `/confirm_task` | `dofbot_info/srv/ConfirmTask` | 看板 → 朱玉贺 | 操作人确认抓取结果 |
| `/trial_service` | `dofbot_info/srv/Kinemarics` | 任务 2 | 正逆运动学解算（内部使用） |

## 2. detect 使用约定（张鹏源）

- 发布到话题 `/detect_result`，字段见 `DetectResult.msg`：`frame_id` 每帧唯一、
  `captured_at_ms` 为采集时刻 Unix 毫秒时间戳。
- 无目标时发布**空 detections 数组**（不要不发布）。
- 置信度低于 0.5 的目标可选择性过滤，但 `fallback=true`（HSV 兜底）的检测**必须发布**，
  闭环会直接采用并标记 `mode=fallback`（对应 9.2 降级路径）。
- 图像超过 1s 未用于生成任务会被闭环丢弃并等待新帧，请保持 ≥1fps 出帧。
- 手势识别字段（待定项 T2）：当前 `DetectResult` 不含手势字段，联调前与
  张鹏源确认扩展方式后同步更新 `dofbot_info`。

## 3. task_command / 状态机（严晨越）

- 看板启动：调用 `/task_command` `{action: start}` → 控制模块执行开机自检
  （读舵机、RGB 循环红绿蓝、蜂鸣器短响）→ 通过后进入 `running`。
  **accepted=true 仅表示接受命令，不代表运动已完成。**
- 看板停止：`{action: stop}` → 停止派发新动作（≤1s），状态先 `stopping` 后回 `idle`。
  软件停止不等同于硬件急停，现场保留硬件断电手段。
- 状态流转：

  ```
  idle --start(自检通过)--> running --stop(运动中)--> stopping --运动终止--> idle
    ^                          |
    |--start(自检)-------------+  fault(超时/驱动错误, 需人工复位: 重新 start)
  ```

- 状态可通过订阅 `/control_status` 实时获取（看板运行监控页建议订阅此话题）。

## 4. task_event 语义（严晨越入库）

- 每个事件 `event_id` 全局唯一，**相同 event_id 不重复入库**（以 event_id 为主键去重）。
- `status` 取值：`queued → running → succeeded / failed / skipped / stopped`。
  - `succeeded`：控制器完成全部动作序列（`result_basis=controller_only`，
    **未确认实际抓取结果，不算已验证成功**）；
  - 看板调 `/confirm_task` 后补发一条同 task_id、`result_basis=operator_confirmed`
    的事件，展示"已验证成功"以确认后的事件为准；
  - `failed`：运动失败（附 error_code）；`skipped`：闭环在提交服务前拦截
    （低置信度/越界等）；`stopped`：因 stop 请求中止。
- 坐标为 null 时 `has_position=false`（ROS2 无 null 类型，以此布尔区分，不使用 0 代替）。
- `mode`：`real`（实机）/ `fallback`（HSV 兜底定位）/ `simulation`（仿真或降级演示）。
- 相同 `task_id` 控制模块不会重复执行（幂等，重复请求返回 `DUPLICATE_TASK`）。

## 5. 错误码（9.1，最低集合 + 扩展）

| 错误码 | 含义 | 处理路径 |
|---|---|---|
| `LOW_CONFIDENCE` | 置信度低于阈值且补采 2 帧仍不足 | skipped + 记录 |
| `OUT_OF_WORKSPACE` | 坐标超出有效工作区 | 拒绝运动，提示重新标定 |
| `CONTROL_TIMEOUT` | 运动 >20s 无终态 | failed + 进入 fault，人工复位 |
| `STOP_REQUESTED` | 收到停止请求 | stopped（≤1s 停止派发） |
| `BUSY` | 已有运动任务在执行 | 拒绝（禁止并行） |
| `NOT_RUNNING` / `FAULT` | 状态不允许执行 | 先 start / 人工复位 |
| `DUPLICATE_TASK` | task_id 重复 | 拒绝（幂等） |
| `NOT_CALIBRATED` / `CALIBRATION_MISMATCH` | 标定缺失/版本不符 | 拒绝，提示标定 |
| `IK_SOLVE_FAILED` | 反解失败（位置不可达） | failed |
| `SELF_CHECK_FAILED` | 自检异常 | 禁止启动 |

## 6. 仿真/降级说明（9.2）

- 驱动层 `driver.mode=auto` 时板卡无 Arm_Lib 会自动降级为**仿真模式**，
  `control_status.mode=simulation`，事件 `mode=simulation`，看板须标注"模拟"，
  不据此声称实机验收通过。
- 联调阶段固定点位演示通过 `/play_action_group`（大自然搬运工/叠罗汉）进行，
  明确标记降级，不计入"工作区任意位置"验收与成功率。
